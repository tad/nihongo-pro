# Nihongo Pro — context for Claude

Personal Japanese-study iPadOS app. SwiftUI, iPadOS 26+ only, single target, zero third-party dependencies.

## Visual identity

- **Palette** (defined in `NihongoPro/Assets.xcassets/`):
  - `AccentColor` — deep indigo (kon-iro), light `#2A3A6B`, dark `#7BA0E0`. Used everywhere SwiftUI reads `.tint` / `.accentColor`.
  - `PaperBackground` — warm cream / off-black. Light `#FFFCF5`, dark `#1A1814`. Applied as `Color.paperBackground.ignoresSafeArea()` behind the main screen, the two modals, and the study session. Auto-generated by Xcode's asset symbol generation (`ASSETCATALOG_COMPILER_GENERATE_SWIFT_ASSET_SYMBOL_EXTENSIONS = YES`), so the property name is `paperBackground` (camelCased from the asset name), not the asset filename.
  - `Vermillion` — warm red-orange (shu-iro), light `#DC4F35`, dark `#F1715A`. Reserved for celebratory moments: correct pre-quiz answers and the session-complete `checkmark.seal.fill`. Not used for primary buttons (those stay indigo accent).
  - `.orange` / `.red` keep their semantic roles (warning / destructive).
- **Card chrome** — `cardChrome(cornerRadius:padding:)` View extension in `NihongoPro/Theme.swift`. Applies `.padding`, `.regularMaterial` rounded background, and a soft shadow (`black.opacity(0.06)`, radius 12, y 2). Used on: the parsed-sentence card on the main screen, the top word-header card in `WordDefinitionView`, every phase card in the study session (vocab pre-quiz, kanji pre-quiz, kanji study, word study, translation critique, session complete).
- **Typography tokens** in `Theme.swift`: `Font.displayKanji` (96pt serif), `Font.displayWord` (72pt serif), `Font.sentenceLarge` (32pt serif). Used across `KanjiDetailView`, `WordDefinitionView`, `StudySessionView` to keep the recurring large display sizes consistent.
- **Motion** — `.smooth(duration: 0.35)` on `session.phase` changes drives slide-left/slide-right transitions between study cards via `.id(session.phase)` + asymmetric `.move` transition. Pre-quiz result icons use `.symbolEffect(.bounce)` + `.transition(.scale.combined(with: .opacity))` with a spring animation. Break overlay scale-fades in via spring. Pomodoro pill's seconds use `.contentTransition(.numericText())` so digits tick rather than snap; icon swaps use `.symbolEffect(.replace)`. The `TextEditor` on the main screen animates its border tint when focus changes (`.smooth(duration: 0.2)`).

## Architecture (locked-in decisions)

- **Multi-pass translation:** pasting/typing into the input area kicks off two sequential Anthropic Messages calls (`claude-sonnet-4-6`, plain `URLSession`) after a debounce. A third on-demand call powers the Breakdown view.
  - **Auto-parse on input change:** `ContentView.handleInputChange()` (wired via `.onChange(of: inputText)`) cancels any in-flight `autoParseTask`, resets parsed state if the text differs from `parsedInputText`, and — when the input is non-empty, single-sentence, and an API key is present — schedules a debounced `Task` that sleeps 800ms then calls `translate()`. The English translation is fetched in the same call but stays hidden until the user reveals it (see below). `translate()` captures the trimmed input at start and bails (without setting state) if `inputText` has changed by the time the network result returns, so racing pastes can't corrupt the display.
  - **Translation reveal:** `isTranslationRevealed` gates whether `englishTranslation` is shown. The "Show translation" button only renders once `words` and `englishTranslation` are populated (i.e., the auto-parse has completed) — there is no impatient-user pathway; the user always sees the Japanese first, then the button appears. Tapping it simply flips `isTranslationRevealed = true`. The Breakdown button only appears post-reveal. `parsedInputText` tracks which input the current `words` / `englishTranslation` belong to so reveals never show a stale translation.
  - **Pass 1 — `TranslationService.translate(_:)`:** returns `{words: [{text, reading, furigana}], translation}`. No definitions. Words/furigana are displayed and the sentence is spoken as soon as it lands so the user can read/hear the sentence; the translation is held back behind the reveal gate. On `.invalidResponseFormat`, `translate(_:)` retries once with the input passed through `sanitizeForJSON(_:)` — which **strips** all quote-like characters entirely (ASCII `"`/`'`, U+201C/D smart double, U+2018/19 smart single, U+201E/A/F low quotes, U+2032/33 primes, U+00AB/BB guillemets, U+301D-F double-prime quotation) and replaces ASCII `\` with `／` (U+FF0F). The original failing input was a sake brewery description containing mixed quote variants; even after replacing them with typographic quotes Claude still produced invalid JSON, so the retry path now drops quote chars entirely as the most reliable recovery. Fidelity tradeoff: quote characters disappear from the output on the retry path, but the sentence parses. `max_tokens` is 8192 here to leave headroom for long sentences with 20+ word entries. JSON extraction (`Self.extractJSON`) is permissive: it strips code fences AND slices from the first `{` to the last `}` so any stray prose around the JSON doesn't break the decode. Parse-failure errors surface (a) detailed `DecodingError` info — `dataCorrupted` unwraps the underlying `NSError`'s `NSDebugDescription`; `keyNotFound`/`typeMismatch`/`valueNotFound` include the coding path — and (b) a generous `previewSnippet` of the raw response (600 head + 600 tail with middle elided), so future failures are diagnosable from the in-app error banner alone.
  - **Pass 2 — `TranslationService.fetchDefinitions(sentence:words:)`:** sends `{sentence, words: [...]}` and gets back `{definitions: [String?]}` aligned to the words by index. `ContentView` merges the array into the existing `words` state (`Word.definition` is `var`). A subtle "Loading word definitions…" indicator appears below the English translation while pass 2 runs; on failure it becomes a "Couldn't load definitions" message with a Retry button.
  - **On-demand — `TranslationService.fetchBreakdown(sentence:words:translation:)`:** fired only when the user taps the Breakdown button. Sends the sentence, the per-word data (including any definitions from pass 2), and the English translation; gets back Markdown with these sections in order: `## Vocabulary`, `## Grammar`, `## Sentence structure`, `## Notes` (the prose commentary). `ContentView.breakdownContent` renders the existing English translation **above** the `BreakdownView` so the reader sees the meaning, then the structural breakdown, then the Notes paragraph at the bottom. The Markdown is cached in `ContentView.breakdown` for the current translation and survives toggling.
  - Three system prompts pinned in `TranslationService.swift` — each includes a worked example to lock in output shape. All three Anthropic calls go through a shared private `sendMessage(systemPrompt:userMessage:maxTokens:)` helper.
- **Tap-to-define:** every word in the Japanese display is a `Button` in `FuriganaText`, disabled while `definition == nil`. The 1.5pt accent underline that marks a word as tappable is also gated on `definition != nil`, so it only appears after pass 2 lands. Tapping a tappable word opens `WordDefinitionView` as a medium-detent sheet showing the word, kana reading, English definition, and a speaker/stop button that plays just that word using the shared `SpeechService`.
- **Tap-to-explore-kanji:** inside `WordDefinitionView`, the large word header is rendered character-by-character. Kanji characters (CJK Unified Ideographs — `Character.isKanji`) become tinted, underlined `Button`s; hiragana/katakana/punctuation render as plain `Text`. Tapping a kanji presents `KanjiDetailView` as a nested medium-detent sheet showing the character, English meanings, on'yomi/kun'yomi readings, a memorable note (all from a Claude call `TranslationService.fetchKanjiInfo(kanji:)`), and a natively-rendered animated stroke order via `KanjiStrokeView`. Stroke data comes from `KanjiVGService.loadSVG(for:)`, which fetches from KanjiVG (`raw.githubusercontent.com/KanjiVG/kanjivg/master/kanji/{codepoint}.svg`) on first request and caches the SVG to the app's `cachesDirectory` for offline reuse. KanjiVG is CC BY-SA 3.0 and the attribution is shown inside `KanjiDetailView`.
- **Study session (work in progress — pomodoro + pre-quiz shipped; study and translation phases pending):** tapping the "Start study" button on the main screen (visible once a sentence is parsed and definitions have loaded) instantiates a `StudySession` (`@MainActor @Observable` class, `Identifiable`) and presents `StudySessionView` via `.fullScreenCover(item:)`. The session builds a `vocabPlan` of unique non-punctuation `Word`s and a `kanjiPlan` of unique kanji characters drawn from those words. A 25-min/5-min pomodoro runs continuously: a `Task` polls every 500ms against a wall-clock end date; when the work timer expires the session calls `AudioServicesPlaySystemSound(1057)` (iOS tri-tone) and switches into break mode (orange overlay locks the UI until the 5-min break ends). The Task is `[weak self]`-guarded so it self-terminates when the session deinits — no explicit `deinit` needed. Each phase advances by mutating `session.phase`; the SwiftUI view re-renders the appropriate card. End-Session button in the toolbar shows a destructive confirmation alert before dismissing.
  - **Vocab list filter:** `StudySession.init` skips pure punctuation AND common grammatical particles (single-char は/が/を/に/で/と/も/か/の/へ/や; sentence-final ね/よ/な/わ/ぞ/ぜ/さ/し; multi-char まで/から/など/だけ/ばかり/しか/でも/けど/けれど/けれども/には/とは/では/のは/のに/ので/って). Set lives in `StudySession.commonParticles`. Copulas (です, だ) are intentionally NOT filtered — they're closer to content than grammar from a study standpoint.
  - **Vocab pre-quiz card:** shows the word, two text fields (definition + pronunciation). Pronunciation accepts either hiragana or rōmaji — `pronunciationMatches(userInput:reference:)` in `StudySessionView.swift` does a direct case-insensitive match first, then transliterates rōmaji → hiragana via `CFStringTransform("Latin-Hiragana")` and compares again. So `kyou` and `kyō` both match `きょう` (no need to switch the iPad keyboard). Definition graded by `TranslationService.evaluateDefinition(item:reference:userAnswer:)` — a Claude call returning `{correct: bool, feedback: string}`. Both must pass for the word to be marked known and removed from `studyVocab`; otherwise it's added to the study list for future phases.
  - **Kanji pre-quiz card:** shows the kanji, one text field (definition). Reference is the cached `KanjiInfo.meanings` joined with commas; if uncached, `TranslationService.fetchKanjiInfo` is called lazily inside `.task(id:)`. Same evaluator endpoint grades the answer.
  - **Kanji study phase:** after the pre-quizzes, items that failed are queued into `studyKanji` (shuffled at phase transition) and presented one-at-a-time by `KanjiStudyCard`. Each card shows the kanji, its meanings, on'yomi/kun'yomi, the memorable note from `KanjiInfo`, and an animated stroke-order diagram (`KanjiStrokeView` driven by KanjiVG SVG, with a Replay button keyed off `animationKey`). Instruction text reads "Write this kanji 5 times on paper, along with its meaning." The user taps "I'm done →" (or presses Return — keyboard shortcut bound) to advance via `session.advanceKanjiStudy()`. Reference data loads in a `.task(id: session.studyKanjiIndex)` so each new card refetches/re-renders.
  - **Word study phase:** failed vocab words queue into `studyVocab` (shuffled at phase transition). `WordStudyCard` shows the reading, the word in large serif, the cached definition, and a tap-to-hear speaker button that drives the shared `SpeechService`. Instruction text reads "Write the word and its definition 5 times on paper, and say the word out loud 5 times." Advance via `session.advanceWordStudy()` (Return-bound).
  - **Phase routing:** `transitionAfterPreQuizzes()` and `transitionAfterKanjiStudy()` handle the routing — empty queues are skipped. Translation is always the final phase: `advanceWordStudy()` lands on `.translation`; sentences with no failed pre-quiz items skip straight to `.translation`.
  - **Translation critique phase:** `TranslationCritiqueCard` shows the original sentence (plain serif text, no furigana — by design, since the student is being tested on understanding rather than reading) and a `TextEditor` for the user's English translation. Auto-focused on appear. Submit calls `TranslationService.critiqueTranslation(sentence:referenceTranslation:userTranslation:)` — a Markdown-returning Claude endpoint (no JSON; just trim + return). The response is rendered by the existing `BreakdownView` mini-Markdown renderer alongside the user's translation and the reference. Finish dismisses the session via the parent's `onFinish` callback (which calls `session.end()` + `dismiss()`), skipping the now-vestigial `SessionCompleteCard`.
  - **Critique tone:** the prompt asks Claude to be warm/encouraging, cite specific Japanese phrases in **bold**, avoid scoring, and stay under 200 words. The worked example in `critiqueSystemPrompt` anchors the style.
- **Familiarity levels (`FamiliarityStore`):** `@MainActor @Observable` singleton (`FamiliarityStore.shared`) tracking a three-tier self-rating per word and per kanji: `.unknown` (default, absent from dict), `.familiar` (stepping stone — purely informational, behaves the same as Unknown), `.known` (graduated — hides furigana, skips study). Two JSON files in `applicationSupportDirectory/NihongoPro/`: `word_familiarity.json` (`[String: Level]`, keyed by `Word.text`) and `kanji_familiarity.json` (`[String: Level]`, keyed by `String(Character)`). Loaded into memory in the init via the same `try? Data(contentsOf:)` + `try? JSONDecoder().decode(...)` pattern as `DefinitionCache`. Setting a level to `.unknown` removes the entry from the dict so files only grow with user-marked items. Writes are dispatched via `Task.detached` (atomic write) so the main thread never blocks. Diverges from the `actor`-pattern used by `DefinitionCache`/`FrequencyTracker` because the store is read synchronously inside SwiftUI view bodies and `StudySession.init` (both `@MainActor`) and changes must drive UI updates reactively — `@Observable` macro tracks the dict accesses for free.
  - **UI:** segmented `Picker` (Unknown / Familiar / Known) provided by two reusable views in `FamiliarityStore.swift`: `WordFamiliarityPicker(word:onKnown:)` and `KanjiFamiliarityPicker(kanji:onKnown:)`. Both write to the store via a `Binding`; if the user sets the level to `.known`, the optional `onKnown` closure fires (dispatched via `Task { @MainActor in onKnown() }` so it runs after the binding-set completes, not mid-SwiftUI-state-mutation). Used in two places:
    1. **Modals** — `WordDefinitionView` (near "Seen N times", above the word header) and `KanjiDetailView` (between "Seen N times" and the kanji glyph). No `onKnown` passed; level is set, modal stays open. No `.task` loader needed — store is in-memory by the time the modal appears.
    2. **Study session cards** — embedded in `VocabPreQuizCard`, `KanjiPreQuizCard`, `KanjiStudyCard`, and `WordStudyCard` (just below the item header, `maxWidth: 360`). Each card passes an `onKnown` closure: pre-quiz cards call the new `session.skipCurrentVocab()` / `session.skipCurrentKanjiPreQuiz()` (advance index, transition phase if done, **don't** append to `studyVocab`/`studyKanji`); study-phase cards call the existing `advanceKanjiStudy()` / `advanceWordStudy()`. Pre-quiz cards also reset their local `@State` (input fields, result, isEvaluating) when skipped — same cleanup as the normal `advance()` path. `WordStudyCard` additionally stops any in-flight speech before advancing.
  - **Furigana suppression:** `FuriganaText.shouldHideFurigana(for:store:)` returns `true` if (a) the word itself is `.known`, OR (b) the word contains at least one kanji and **every** kanji char in `word.text` is `.known`. The boolean threads into `WordView` as `hideFurigana` and gates the ruby `Text(...).opacity((hideFurigana || seg.reading == nil) ? 0 : 1)` — opacity (not conditional render) preserves the row's vertical layout. The 1.5pt accent underline and the wrapping `Button` are untouched, so Known words remain tappable to demote back to Familiar/Unknown.
  - **Study-session filter:** `StudySession.init` consults `FamiliarityStore.shared` while building `vocabPlan` (skips words where `wordLevel == .known`) and `kanjiPlan` (skips chars where `kanjiLevel == .known`). The init is `@MainActor`-isolated so the sync read works. Empty-plan fallback: if both plans end up empty after filtering, the session jumps straight to `.translation` (not `.completed`) so the user still gets to translate the sentence.
- **Exposure counters (`FrequencyTracker`):** actor singleton (`FrequencyTracker.shared`) tracking how many times each word (surface form) and each individual kanji has appeared in a successfully parsed sentence. Two JSON files in `applicationSupportDirectory/NihongoPro/`: `word_frequencies.json` and `kanji_frequencies.json` (both `[String: Int]`). `recordSentence(words:)` is called from `ContentView.translate()` immediately after `words = result.words` — it iterates the words, incrementing each `word.text` count, and for each `Character` in `word.text` where `isKanji` it increments that kanji's count. Single batch write per file per parse (not per increment). `WordDefinitionView` and `KanjiDetailView` each read their respective count in a `.task` modifier on appear and render `"Seen N times"` (or `"Seen 1 time"`) as a small `.caption .secondary` label at the top-left of the modal. The current parse counts, so the modal you just opened never shows 0. Pasting the same sentence twice = +2 (intentional — counts exposures, not unique sentences).
- **Persistent definition cache (`DefinitionCache`):** actor singleton (`DefinitionCache.shared`) that backs both `fetchKanjiInfo(kanji:)` and `fetchDefinitions(sentence:words:)`. Two JSON files in `applicationSupportDirectory/NihongoPro/`: `kanji_cache.json` (`[String: KanjiInfo]`) and `word_cache.json` (`[String: String]`). Files are loaded into memory in the actor's init and persisted on every set call (atomic write). Cache hits skip the Claude round-trip entirely.
  - **Kanji:** keyed by the kanji character. `fetchKanjiInfo` checks cache first; on miss, calls Claude and stores the result. `KanjiInfo` is `Codable`.
  - **Word definitions:** keyed by surface form (`Word.text`), stored in `word_definitions.json`. `fetchDefinitions` does **partial fetch**: for each input word it (a) marks it `nil` if `isPurePunctuation(_:)` (CharacterSet of `.punctuationCharacters` + `.whitespacesAndNewlines`), (b) pulls from cache if known, (c) collects the rest as `uncachedIndices`. If `uncachedIndices` is empty, no API call is made. Otherwise the sentence is sent with just the uncached words; returned definitions get spliced back into the original indices.
  - **Polysemy guard:** the definitions response includes a `context_dependent: [bool]` array aligned with `definitions`. Claude marks `true` for polysemous words whose meaning varies meaningfully across common contexts (走る, 開く, 持つ, 出る, 取る, 立つ, 上がる…) and `false` for words with one dominant sense (今日, 食べる, particles, copulas). Only definitions where `context_dependent == false` are written to the cache. If the flag is missing/malformed, the iOS side defaults to `true` (don't cache) — fail-safe. The polysemy guidance lives in `definitionsSystemPrompt`. On app upgrade to this version, the actor's `init` deletes the legacy `word_cache.json` (entries may include polysemous words from before the flag existed) and starts fresh in `word_definitions.json`.
- **Stroke renderer:** `KanjiStrokeView` is fully native SwiftUI (no WKWebView). `extractStrokes(from:)` finds the `kvg:StrokePaths` section in the SVG with a regex and extracts each `<path d="...">`. `SVGPathParser.parse(_:)` (adapted from the sibling **kanji-concept** project) converts each d-string into a SwiftUI `Path` plus the start point of the first subpath. `StrokeAnimator` (`@StateObject`, MainActor `ObservableObject`) sequences per-stroke `withAnimation(.linear)` trims with duration scaled by the stroke's bounding-box diagonal. `StrokeCanvas` renders a 109-unit square with a faint grid + dashed crosshair, completed strokes at `Color.primary.opacity(0.25)`, the active stroke at full `Color.primary`, and an 18pt accent-color numbered badge at each stroke's start point. Replay is implemented by `.id(animationKey)` on the view; bumping the key forces a fresh parse + `animator.play(strokes:)`.
- **Breakdown view:** a Breakdown button sits to the right of Translate. Tapping replaces the English translation with the Markdown breakdown rendered by `BreakdownView` (custom mini-renderer handling `#`/`##`/`###` headings, `-`/`*` bullets, paragraphs, and inline `**bold**` / `*italic*` via `AttributedString`) and **hides the Breakdown button itself** — the action is one-way for the current sentence. Tapping Translate (with the same or different input) resets `showingBreakdown` to false and brings the Breakdown button back. The Markdown is cached in `ContentView.breakdown` for the lifetime of the current translation.
- **Clear button:** a destructive-role `.bordered` Clear button sits on the bottom-left of the action row (a `Spacer()` separates it from Show translation/Breakdown on the right). `ContentView.clear()` cancels any pending `autoParseTask`, resets `inputText`, `words`, `englishTranslation`, `isTranslationRevealed`, `parsedInputText`, all error/breakdown/loading state, and calls `speechService.stop()` if audio is still playing. Disabled while a translation is in flight or when there is nothing to clear (empty input AND empty results AND no error).
- **Spoken Japanese (TTS):** `SpeechService` wraps `AVSpeechSynthesizer` for on-device Japanese TTS (ja-JP). Voice selection respects a user-chosen `AVSpeechSynthesisVoice.identifier` stored in `UserDefaults` under `speechVoiceIdentifier`; empty/unset falls back to the highest-quality installed ja-JP voice (premium > enhanced > default). Playback fires automatically **after** the Claude response lands (so the audio is synchronized with the visual reveal of the furigana + translation) and on demand via a speaker/stop button in the Japanese display area. Failed requests do not play audio. Rate is configurable in Settings (Natural / 85% / 65%) under key `speechRate`. The Settings sheet lists every installed ja-JP voice with a Play Sample button.
- **API key storage:** iOS Keychain (`kSecClassGenericPassword`, service `com.terrydonaghe.NihongoPro`, account `anthropic-api-key`). Entered in-app on first launch via `SettingsView`; re-openable via gear icon. No xcconfig/Secrets file.
- **Dependencies:** none third-party. System frameworks only: Foundation, SwiftUI, Security (Keychain), AVFoundation (TTS). Network data: KanjiVG (CC BY-SA 3.0, fetched on demand). No SPM, no CocoaPods.
- **Trigger:** debounced auto-parse on `inputText` change (800ms). Translation reveal is gated behind the **Show translation** button so the user can attempt to read the sentence first.
- **Device target:** iPad only (`TARGETED_DEVICE_FAMILY = 2`), iPadOS 26+ (`IPHONEOS_DEPLOYMENT_TARGET = 26.0`).
- **Bundle ID:** `com.terrydonaghe.NihongoPro`.

## Build & run

Open `NihongoPro.xcodeproj` in Xcode and Run on an iPad simulator. Headless build for verification:

```bash
xcodebuild -project NihongoPro.xcodeproj -scheme NihongoPro \
  -destination 'generic/platform=iOS Simulator' \
  -configuration Debug build CODE_SIGNING_ALLOWED=NO
```

Always run this after editing Swift files or pbxproj — SourceKit diagnostics shown during edits are noisy and unreliable; the actual build is the source of truth.

## Adding a new Swift source file

The pbxproj uses readable sequential IDs of the form `FA00000000000000000000{XY}`. When adding `NewFile.swift`:

1. Pick the next unused suffix (e.g. `A9` for the file ref, `B9` for the build file).
2. Add a `PBXFileReference` line in the PBXFileReference section.
3. Add a `PBXBuildFile` line in the PBXBuildFile section.
4. Add the file ref `A9` to the `FA00000000000000000000D1 /* NihongoPro */` group's `children`.
5. Add the build file `B9` to the `FA00000000000000000000E1 /* Sources */` build phase's `files`.
6. Rebuild with the xcodebuild command above.

Existing IDs in use:
- `A1`–`A5`: original Swift source files; `A6`: Info.plist; `A7`: Assets.xcassets; `A8`: FuriganaText.swift; `A9`: WordDefinitionView.swift; `AA`: SpeechService.swift; `AB`: BreakdownView.swift; `AC`: KanjiVGService.swift; `AD`: KanjiStrokeView.swift; `AE`: KanjiDetailView.swift; `AF`: SVGPathParser.swift; `B0`: DefinitionCache.swift; `B6`: FrequencyTracker.swift; `C2`: StudySession.swift; `C4`: StudySessionView.swift; `C7`: Theme.swift; `C9`: FamiliarityStore.swift
- `B1`–`B5`, `B7`–`B9`, `BA`–`BF`, `C0`, `C3`, `C5`, `C6`, `C8`, `CA`: matching PBXBuildFile entries
- `C1`: app product; `D0`–`D2`: groups; `E1`–`E3`: build phases; `F00`/`F1`: project/target; `101`–`104`, `111`–`112`: configs

## Tuning behavior

- **Translation/furigana quality:** edit `translationSystemPrompt` in `TranslationService.swift` (pass 1). Definition quality lives in `definitionsSystemPrompt` (pass 2). Breakdown depth and structure live in `breakdownSystemPrompt`. Per-kanji info shape lives in `kanjiInfoSystemPrompt`. Keep the worked example in each prompt — they reliably anchor Claude's output shape (JSON for passes 1/2/kanji, Markdown for breakdown).
- **Stroke order animation:** `KanjiStrokeView` is fully native SwiftUI (see Tap-to-explore-kanji above for the render pipeline). To tune the look: stroke thickness, completed-stroke opacity, badge size, and grid/dash colors all live in `StrokeCanvas` inside `KanjiStrokeView.swift`. Per-stroke duration scaling lives in `StrokeAnimator.duration(for:)`. Replay is implemented by bumping `KanjiDetailView.animationKey` which `.id()`-keys the `KanjiStrokeView` — SwiftUI discards and recreates the view, which re-parses the SVG (cheap, ~ms) and starts a fresh `animator.play(strokes:)`. Cache directory for fetched SVGs is `FileManager.default.urls(for: .cachesDirectory, ...)` so files may be evicted under disk pressure; refetch is automatic.
- **Furigana display:** `FuriganaText` view exposes `baseFont`, `rubyFont`, `rubyColor`, `wordSpacing`, `lineSpacing`, and `onWordTap` parameters. Each word is wrapped in a `Button` and disabled when `definition == nil` (punctuation). Tappable words get a 1.5pt `.tint`-colored underline via a bottom overlay inside `WordView`; punctuation gets no underline. The flow-wrap logic is `FuriganaFlowLayout` in the same file. Note: wrapping words in `Button` removes per-character text selection on the Japanese display in exchange for tap-to-define; the English translation below remains selectable.
- **Definition sheet:** `WordDefinitionView` is a small SwiftUI view shown via `.sheet(item:)` with `.presentationDetents([.medium, .large])`. The selection state lives in `ContentView.selectedWord: WordSelection?` (a UUID-id wrapper around `Word` so `.sheet(item:)` works even when the same word appears twice). The sheet receives the shared `SpeechService` via init (`@ObservedObject`) so its play/stop button reflects the same `isSpeaking` state as the main display — closing the sheet while audio is still playing does not stop it.
- **TTS tuning:** voice selection priority is in `SpeechService.selectedVoice()` (UserDefaults override → `bestJapaneseVoice()` fallback). Quality-tier fallback is in `bestJapaneseVoice()` / `availableJapaneseVoices()` — change the sort order to change auto-pick behavior. Rate multipliers are in `SpeechRate.multiplier`. Audio session uses default `.ambient` so the device silent switch silences playback; to force playback regardless, set `AVAudioSession.sharedInstance().setCategory(.playback)` in `init()`. `SettingsView` reads `SpeechService.availableJapaneseVoices()` to populate its Voice picker — `SettingsView` takes the live `SpeechService` instance via init so the Play Sample button shares state with the main display.
- **Input validation:** `ContentView.isMultiSentence(_:)` uses `String.enumerateSubstrings(in:options: .bySentences)` (ICU's sentence breaker — handles 。!?！？ and quoted text reasonably) to count sentences; >1 disables the Translate button and shows an inline orange warning below the text editor. Long single sentences are intentionally allowed — there is no character limit, only a sentence-count limit.
- **Model:** `TranslationService.model` constant. Sonnet 4.6 is the chosen balance; Haiku is cheaper but weaker on idiomatic readings, Opus is overkill for sentence-level.
